# 总结

1. sys_get_time
    任务是给定一个虚拟地址，将时间写入地址。那么首先就先检查这块区域对用户是否是可写的，然后获取时间后填入地址，对于不同情况，我直接用if分支解决了，没想到很好的通用解法。

2. sys_trace
    trace_request为0或1时，在获取前分别判断是否可读或可写，然后用translated_byte_buffer获取物理地址

3. sys_mmap
    通过memory_set的insert_framed_area方法实现，为了处理错误传播改了一部分自带的函数

4. sys_munmap
    仿照申请内存的方法，给memory_set写了个remove_area方法，调用pagetable的unmap方法释放内存，不过只实现了删除页表项，没对MapArea处理。

# 简答题

1. 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？

    页表项低8位是标志位，8、9位是保留位，给supervisor软件使用，10-53存储PPN，其他为是保留位。
    0 V: 表示该PTE是否有效
    1 R: 表示是否可读
    2 W: 表示是否可写
    3 X: 表示是否可执行
    4 U: 表示U模式下能否访问
    5 G: 表示全局映射，转换虚拟空间时不会刷新它的TLB
    6 A: 表示被访问 R+W+X
    7 D: 表示被修改 W

2. 缺页
    缺页指的是进程访问页面时页面不在页表中或在页表中无效的现象，此时 MMU 将会返回一个中断， 告知 os 进程内存访问出了问题。os 选择填补页表并重新执行异常指令或者杀死进程。

    请问哪些异常可能是缺页导致的？
    1. 异常号12 Instruction page fault，当进程尝试从缺页地址读指令时
    2. 异常号13 Load page fault, 当读取缺页地址
    3. 异常号15 store page fault, 当写入缺页地址

    缺页有两个常见的原因，其一是 Lazy 策略，也就是直到内存页面被访问才实际进行页表操作。 比如，一个程序被执行时，进程的代码段理论上需要从磁盘加载到内存。但是 os 并不会马上这样做， 而是会保存 .text 段在磁盘的位置信息，在这些代码第一次被执行时才完成从磁盘的加载操作。

    这样做有哪些好处？
    
        主要是为了节省物理内存，因为同一时间运行程序只需用到其中的一部分代码和数据。其次这样可以减少IO操作，加速程序启动速度。

    其实，我们的 mmap 也可以采取 Lazy 策略，比如：一个用户进程先后申请了 10G 的内存空间， 然后用了其中 1M 就直接退出了。按照现在的做法，我们显然亏大了，进行了很多没有意义的页表操作。

    处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？
    
       需要 10G / 4KB = 10 * 2^18个页表项，需要 10 * 2^9个三级页表， 10个二级页表， 1个一级页表，因此大概需要20M内存

    请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现。

        只初始化MapArea对象，记录范围和权限，或者只初始化前两级页表，因为主要的消耗是初始化三级页表带来的。当遇到缺页异常时可以在trap_handler中判断目标虚拟地址是否在map_area范围内，且是否合法，然后再完成当前地址的映射，同时也可以映射相近地址，减少中断频率。

    缺页的另一个常见原因是 swap 策略，也就是内存页面可能被换到磁盘上了，导致对应页面失效。

    此时页面失效如何表现在页表项(PTE)上？

        V位被置0表示失效，但此时这个页表项可能还需要指向磁盘位置，可以用RSW两位表示这种特殊状态。

3. 双页表和单页表

    为了防范侧信道攻击，我们的 os 使用了双页表。但是传统的设计一直是单页表的，也就是说，用户线程和对应的内核线程共用同一张页表，只不过内核对应的地址只允许在内核态访问。 (备注：这里的单/双的说法仅为自创的通俗说法，并无这个名词概念，详情见 KPTI )

    在单页表情况下，如何更换页表？

        先进入内核态，然后更新satp寄存器

    单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）
        
        将内核页面PTE的U位置0

    单页表有何优势？（回答合理即可）

        在内核态与用户态之间切换时不需要切换页表，因此不用刷新TLB，且延迟更低，页表占用内存也更小。

    双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？

        在双叶页表实现下，需要在切换特权级和切换进程（任务）时更换页表。在单页表系统中，只需要在进程切换时更换页表。
